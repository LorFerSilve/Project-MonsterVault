## 4. Lease Matrix

|---|---|---|
| no lock | Acquiring | claim new lock |

## 5. Load Outcome Matrix

| Condition | Result |
|---|---|
| key missing with successful DataStore access | create current default profile + lease |
| valid current schema | lease + validate -> Ready |
| valid older supported schema | atomic migration + validate -> Ready |
| schema newer than server | fail closed; no downgrade |
| transient DataStore error | bounded retry; not a new profile |
| foreign fresh lease | SessionLocked; no writable profile |
| structurally invalid profile | ProtectedLoadFailure/operator recovery |
| migration fails | old stored version preserved; ProtectedLoadFailure |
| load error followed by server default object existing in memory | must never be saved over old key |

## 9. Multi-Key Rule

Roblox provides no general all-or-nothing multi-key DataStore transaction primitive.

Therefore cross-key workflows must use a recoverable journal/state machine rather than pretend sequential writes are atomic.

Mandatory properties:

- stable transaction ID;
- immutable participant identities;
- durable commit decision;
- idempotent participant application;
- safe resume after crash;
- no conflicting session writer;
- observable terminal outcome.

## 10. Schema / Migration Matrix

| Profile version | Server code | Result |
|---|---|---|
| missing/new | current | create current default |
| current | current | validate |
| older supported | current | sequential pure migrations |
| older unsupported without migration path | current | ProtectedLoadFailure |
| newer than current server | older rollback server | fail closed; no downgrade |
| migration produces invalid state | current | abort/no partial write |

## 11. Recovery Matrix

| Failure | Automatic response | Manual/ops response |
|---|---|---|
| transient DataStore timeout | retry/backoff/jitter | observe if persistent |
| throttling | budget-aware retry | tune TA-14/traffic |
| fresh session lock | wait/retry/protected | investigate only if anomalous |
| stale session lock | reclaim after expiry | none normally |
| lost lock mid-session | stop writes/irreversible actions | investigate concurrency |
| corrupt current profile | protected failure | inspect versions/recover |
| bad deployment schema | fail newer/invalid safely | rollback code only if schema-compatible; otherwise forward fix |
| accidental bad write | protected/ops workflow | Data Store version revert |
| server crash | next server waits for stale lease + loads last durable checkpoint | diagnostics/compensation only if needed |
