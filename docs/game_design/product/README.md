# Product Vision, Audience, and Success Criteria

> **Status:** Design Complete  
> **Owning phase:** GDS-1 — Product Vision, Audience, and Success Criteria  
> **Authority:** High-level product identity, audience, positioning, session promise, commercial boundaries, and product success gates

This directory contains the authoritative GDS-1 product specifications for MonsterVault.

GDS-1 fixes the high-level product contract that later gameplay systems must serve. It does **not** define subsystem mechanics such as exact capture probability, rarity tables, economy formulas, trading state machines, event cadence, or monetization products; those remain owned by later GDS phases.

## Authoritative Specifications

- [`target_audience_and_platform.md`](target_audience_and_platform.md) — primary/secondary audience, device priority, communication independence, and broad accessibility target.
- [`market_positioning_and_differentiation.md`](market_positioning_and_differentiation.md) — category position, product promise, differentiation, competitive boundaries, and clone-avoidance rules.
- [`session_shape_and_experience_promise.md`](session_shape_and_experience_promise.md) — intended first-session pacing and repeat-session shape.
- [`success_criteria_and_product_gates.md`](success_criteria_and_product_gates.md) — measurable validation criteria and go/no-go rules.
- [`scope_and_commercial_boundaries.md`](scope_and_commercial_boundaries.md) — high-level scope discipline, trading/monetization/live-ops position, and non-goals.
- [`PLATFORM_AND_MARKET_CONTEXT.md`](PLATFORM_AND_MARKET_CONTEXT.md) — dated external evidence used during GDS-1; evidence only, not gameplay authority.

The high-level synthesis is owned by [`../01_game_overview.md`](../01_game_overview.md).

## GDS-1 Rule

Later phases may add detail but may not silently violate these product-level constraints. If a later mechanic would materially alter the target audience, core fantasy, product positioning, competitive intensity, session promise, commercial fairness, or validation hierarchy, GDS-1 must be reopened through the design-decision process.
