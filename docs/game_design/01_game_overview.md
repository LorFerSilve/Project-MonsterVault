# MonsterVault Game Overview

> **Status:** Draft
> **Owning GDS phase:** GDS-1 — Product Vision, Audience, and Success Criteria
> **Authority:** High-level product direction only

## Current Working Pitch

MonsterVault is a multiplayer Roblox creature-collection and progression game built around a fast-to-understand active loop, long-term collection value, visible progression, social competition/cooperation, rare variants, server-wide events and a live-content model that can expand over time.

## Working Core Loop

```text
Explore
  -> discover creature
  -> attempt capture
  -> secure / transport / return
  -> add to collection or vault
  -> gain production/progression value
  -> upgrade capacity/equipment/access
  -> unlock harder or rarer content
  -> discover mutations and high-status variants
  -> participate in social/server events
  -> repeat
```

This loop is a design hypothesis, not yet an implementation contract.

## Working Product Pillars

1. **Immediate comprehension** — a new player should quickly understand the next meaningful action.
2. **Collection desire** — creatures, rarity and mutations should create durable collection goals.
3. **Visible progression** — progress should be legible in the world, collection and player capabilities.
4. **Active risk/reward** — valuable captures should involve active decisions rather than only idle accumulation.
5. **Social stories** — events, competition, cooperation and status should create memorable multiplayer moments.
6. **Live-content extensibility** — new creatures, mutations, biomes and events should be able to extend the game without redesigning the core loop.
7. **Commercial sustainability without destructive pay-to-win** — monetization should support the product without invalidating earned progression or player trust.

## Current Differentiation Hypothesis

The intended differentiation is not simply "another pet collector" or "another steal game". The current hypothesis combines:

- collectible creatures with meaningful individual rarity/variant identity;
- an active capture/secure/return loop;
- a personal vault/laboratory that makes the collection visible and useful;
- mutation combinations that generate status and scarcity;
- server-level events that create shared competition/cooperation;
- an eventual trading economy governed by strong ownership and value-integrity rules.

## Current Vertical-Slice Hypothesis

The old foundation proposed a small playable slice containing roughly one biome, one vault, a limited creature pool, a small rarity/mutation set, capture, passive production, upgrades, one server event and persistence.

That scope is now treated as **historical planning input only**. The final vertical slice will be derived later from the completed GDS and TA, not assumed in advance.

## Open Product Questions

GDS-1 must resolve at minimum:

- precise target player profile and age expectations;
- desired average session shape;
- mobile-first vs equal-platform priority;
- how competitive the product should feel;
- how much direct player conflict is desirable;
- whether transport/interception is core or optional;
- intended emotional tone and visual identity;
- long-term progression horizon;
- trading launch scope vs post-launch scope;
- acceptable monetization intensity;
- live-ops cadence assumptions;
- launch content scope;
- measurable success criteria for onboarding, retention, social play and monetization.

Until those questions are resolved, this document remains `Draft`.
